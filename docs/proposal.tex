\subsubsection*{Project summary}
We propose to extend Smurfs with evidence-aware shared memory and test whether checking recalled evidence prevents stale information from affecting later decisions. The project combines one memory intervention, controlled evidence/error experiments, and a reproducible benchmark harness. No performance improvements are claimed at this planning stage.\par

\section{Motivation and research questions}
Planning, execution, answering, and verification roles share information. Compressed memory may omit a constraint or become outdated after new evidence arrives. Reusing that memory can propagate an error across roles and subsequent tasks.\par

For example, after a user reduces a travel budget, later roles might reuse an old plan without checking the changed constraint. This is an illustrative scenario, not an experimental observation.\par

\begin{itemize}
\item \textbf{RQ1 - Memory utility:} Does tiered memory improve recall and subsequent task completion over recent history and ordinary retrieval?
\item \textbf{RQ2 - Evidence and recovery:} Does checking evidence validity reduce stale-information reuse across roles and improve recovery after an update?
\item \textbf{RQ3 - Resource trade-offs:} How do evidence budgets and task concurrency affect quality, cost, and completion time?
\end{itemize}
\subsubsection*{Current scope}
\begin{itemize}
\item \textbf{Backbone and memory:} fix Smurfs; pilot Jev TierMem as the first memory backend.
\item \textbf{Evaluation:} LongMemEval and STALE, with a small MemoryArena action pilot and MAST-informed failure annotation.
\item \textbf{Deliverables:} a memory adapter, source-linked traces, error analysis, and reproducible comparisons. No parameter training is required initially.
\end{itemize}
Sections 2-3 compare research alternatives; Section 5 adds five implementation choices.\par

\subsubsection*{Dataset decision}
Use two primary memory evaluations and one action pilot. These are not a training/test pair: no model parameters are trained. Reserve disjoint development groups for tuning. STALE uses LongMemEval-derived distractors; audit overlap and disclose dependence.\par

\section{What we will build}
\subsubsection*{A. Memory integration and one intervention}
Connect Smurfs to a replaceable adapter with immutable source IDs. For authoritative updates, check summary validity, flag dependent conclusions, and recover raw evidence within budget. Preserve old records and uncertainty. Study these existing ideas at role handoffs; test implicit conflicts without gold update labels.\par

\subsubsection*{B. Evidence and error experiments}
Use update/no-update cases to track stale reads, cross-role reuse, and recovery with a MAST-informed rubric. Keep stress-suite and official MemoryArena scores separate.\par

\subsubsection*{C. A shared benchmark harness}
Run matched conditions with isolated stores and saved traces/costs. Recompute metrics and run a limited evidence-budget/concurrency sweep.\par

\section{Implementation choices beyond agents, memory, and data}
These choices define how the selected components work together. They are project decisions, not measured comparisons. Freeze pending choices after the feasibility pilot.\par

\subsection{Model and provider configuration}
\textbf{Options:} hosted API models or local model serving.\par

\textbf{Initial direction:} use a configurable API client and one fixed task/answer model across conditions. Choose provider, model/version, and spending cap after checking access, tool calls, context limits, and cost. Record Jev's separate service and scoring models. Local serving is optional.\par

\subsection{Integration boundary}
\textbf{Options:} a direct Python adapter or a separate MCP/HTTP service.\par

\textbf{Selected:} use Python calls to Jev's {\small\texttt{observe()}}, {\small\texttt{add\_summary()}}, and {\small\texttt{retrieve()}} \cite{jev2026}. Keep {\small\texttt{promote()}} write-back explicit. Smurfs generates answers; extend its verifier to receive evidence. Keep a replaceable interface within one process initially.\par

\subsection{Storage, retrieval, and memory scope}
\textbf{Options:} Jev's local stores, an added vector database, or a shared memory service.\par

\textbf{Selected:} reuse Jev's SQLite/FTS5 raw store and file-based summaries \cite{jev2026}. Add source IDs, update links, and validity metadata in the adapter. Serialize writes within groups; isolate groups and conditions. Keep retrieval infrastructure fixed across the intervention comparison.\par

\subsection{Action environment and tool access}
\textbf{Options:} MemoryArena travel tools, browser/file workflows, or domain simulations.\par

\textbf{Proposed:} wrap one MemoryArena travel environment \cite{memoryarena2026}, subject to database access and a complete pilot trace. Match tools and limits across conditions. If infeasible, retain controlled cross-role tests and narrow claims; QA accuracy does not establish action success.\par

\subsection{Evaluation, traces, and execution}
\textbf{Options:} custom end-to-end judging and an external tracking stack, or official scorers with portable local artifacts.\par

\textbf{Selected:} official score wrappers plus B's evidence/recovery rubric and human checks. C owns a Python runner, versioned configs, JSONL events, and CSV summaries. Freeze judges and sampling; log calls and failures. Run isolated groups concurrently. Dashboards, distributed scheduling, and GPU experiments are optional.\par

\section{Experimental design}
\subsection{Comparisons and ablations}
\begin{itemize}
\item \textbf{Memory QA:} recent history, BM25 over identical raw chunks, unmodified Jev, and Jev plus our intervention. Fix the answer model; disclose additional models.
\item \textbf{Closest method:} CUP-Mem on a matched STALE subset, subject to pilot feasibility. If unavailable, disclose the missing comparison and narrow claims.
\item \textbf{Actions:} Smurfs without persistent memory, with Jev, and with our intervention; hold tools, observations, models, and limits constant.
\item \textbf{Ablations:} disable validity filtering or raw-evidence recovery separately. Claims about multi-agent benefits require a budget-matched single-agent control.
\end{itemize}
\subsection{Data isolation and experimental scale}
Split by complete history, scenario, or task group. Gold answers, evidence-location labels, conflict explanations, and scoring state remain evaluator-only. Retain intended multi-session history but isolate stores across groups and conditions; fix query-level write-back policy. LongMemEval S, M, and oracle are context settings, not splits.\par

Pilot 10 development units per primary dataset and 3 travel groups. Provisionally target 100 held-out LongMemEval questions, 100 STALE scenarios, and 20 travel groups after cost estimation. Freeze IDs, prompts, models, judge, and budgets. Report coverage and counts; aim for three repetitions where affordable, with uncertainty grouped by history/scenario/task.\par

\subsection{Quality, evidence, and recovery metrics}
Use official scorers, category-level results, and human checks. Distinguish citation existence, evidence recall, and semantic support. For update cases:\par

\begin{itemize}
\item \textbf{Stale-use rate:} stale-dependent decisions / eligible post-update decisions.
\item \textbf{Cross-role propagation rate:} update episodes with stale evidence reused by another role / update episodes.
\item \textbf{Recovery rate:} corrected, successful episodes / update episodes.
\end{itemize}
Report denominators, failures, reviewer disagreement, and representative successful and failed traces.\par

\subsection{Resource benchmark}
Vary evidence budget and concurrency (1, 2, 4) separately on a fixed subset, holding tools and retry policy constant.\par

Count all role, summary, retrieval, Jev, and retry calls, including failed runs. Separate ingestion, execution, and evaluation-judge costs. Report tokens, requests, throughput, and latency including queue time; unknown usage is not zero. Label injected delays as synthetic. API results do not establish GPU utilization or hardware-scheduling performance.\par
